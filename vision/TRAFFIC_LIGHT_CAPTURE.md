# 红绿灯视觉采集

当前阶段采集真实图像与人工标签，不实现车辆放行或刹车。工具运行在电脑，使用车端已有8080预览服务，只发GET请求；不打开第二个摄像头设备，不访问UART，不重启车端服务，不改变斑马线程序。

## 技术栈：本次实际使用的组件

| 层 | 技术与版本 | 具体职责 |
|---|---|---|
| 车端已有平台 | Raspberry Pi 5、Linux、Python；USB UVC/V4L2、MJPG | 既有服务独占两路摄像头，提供原始预览JPEG与状态；此次不改车控服务 |
| 电脑采集后端 | Python 3.12.14；标准库 `http.server`、`urllib.request`、`threading` | 读取两路HTTP画面、运行本地8091服务、冻结帧缓存、保存图像和标签、录制有时间记录的帧序列 |
| 图像处理 | OpenCV 4.11.0、NumPy 2.2.6 | JPEG解码、HSV分色、灯组几何与亮度比较、画质指标、框坐标处理 |
| 页面前端 | 原生HTML5、CSS、JavaScript；Canvas、Fetch API | 显示真实图像、冻结和拖框、人工灯色标签、采集按钮与样本计数；没有React/Vue构建依赖 |
| 通信 | 既有5G＋Tailscale；HTTP GET | 电脑访问车端8080；采集页位于电脑 `127.0.0.1:8091`，所有写操作只写本机数据，不转发车辆控制指令 |
| 数据格式 | 原JPEG字节、UTF-8 JSON／JSONL、CSV | 原图、人工标签、算法参考、场景条件、时间信息与批次清单分开保存；不依赖数据库 |
| 软件检查 | pytest、Node.js语法检查 | 后端保存／标签／冻结／权限／序列测试与原生JavaScript语法检查；Node.js不是运行采集工具所必需的后端 |

数据流：USB双摄 → 树莓派既有摄像头服务 → 5G/Tailscale上的HTTP预览 → 电脑Python采集进程 → 浏览器Canvas显示与人工标注 → 电脑本地文件。

当前参考识别是**传统OpenCV算法**：HSV颜色线索、Canny边缘与椭圆灯罩、横向三灯相对位置、发光亮度／色晕对比，以及连续绿灯确认。已根据154张人工标签做开发回放，推荐主USB2.0摄像头；H65过曝严重，不作为红绿灯通行判断源。结果可以为未知，永远不会替代人工正确标签。没有启用新YOLO权重、ROS或云端图像上传，详见 `TRAFFIC_SIGNAL.md` 的完整结果和限制。

主要代码：`tools/traffic_capture.py` 是运行入口；`src/carvision/traffic_capture.py` 管理图像、冻结和标签；`src/carvision/traffic_capture_server.py` 管理只读车端连接与本地接口；`web/traffic_capture.html` 是真实图像采集页面；已有 `traffic_lamps.py` 提供算法参考。

## 打开与运行

采集页：`http://127.0.0.1:8091/`。这是本机真实摄像头采集页，其他电脑不能用这个地址访问本机。

从项目根目录启动：

```powershell
.\vision\run-traffic-capture.ps1
```

如需显式指定车端地址：

```powershell
.\vision\run-traffic-capture.ps1 -Preview http://100.124.156.117:8080
```

直接运行入口：

```powershell
.\.venv\Scripts\python.exe vision/tools/traffic_capture.py --preview http://100.124.156.117:8080 --port 8091
```

程序把数据保存到电脑项目内 `data/raw/traffic_lights/<批次>/`。关闭浏览器标签不结束后台服务；页面底部“退出采集程序”会正常结束并保留已保存数据。

## 先怎样摆放

用户提供的2026规则初稿第6页写明：灯体60×17×6.7 cm，居中架在赛道上方，底部离地40 cm；图7为横向三灯。第7页规定灯前1 m的光电传感器触发3–10秒随机倒计时，绿灯后才能通行，停车时前轮不得超出传感器到灯具之间的区域。

据此先用真实比赛灯具做采集。保持车载摄像头角度不变，电调关闭，车辆静止；可移动灯具或手推断开动力的车辆改变摆位。软件不会替你驱动车辆。如果手头灯具与规则模型不同，在“布局”和“备注”里如实记录，不默认它就是最终比赛灯。

采集距离统一量“**前轮最前缘到灯体地面投影**”。没有用尺量就留空，不从图像猜距离，也不沿用斑马线的车头距离标定。

## 静态采集步骤

1. 看两路真实画面，选灯具更清楚的一路；软件支持主USB2.0和第二路H65，先都留一些对比图，不预先认定哪路最终负责红绿灯。
2. 每换一个摆位或光照，点击“新建场景批次”，填写场景名、尺量距离、光照、真实布局。
3. 点“冻结当前画面”，核对真正亮的是哪一个灯。需要灯体框时，在对应画面拖框；拖框也会自动冻结。框住整套灯具外壳，不只框发光圆点。
4. 点“红灯／黄灯／绿灯／全灭／无灯具／切换／待标注”保存。只保存所选相机；需要另一相机时切换“当前保存哪一路”。
5. 保存后自动恢复实时画面。选错标签可在“本批次采集与历史标注”里更正，原图不会改变。点缩略图可看原尺寸图片。

“全灭”是画面有灯具但没有发光；“无灯具”是负样本。不能把红色灯罩当成红灯正在亮。看不清、两灯同时亮、切换瞬间分别标“待标注”或“切换”，不要猜成绿灯。算法参考只是旧的横排灯启发式结果，绝不自动写成人工标签。

冻结图最多保留5分钟。断流或没有新鲜画面时不能新拍；已经冻结的原图仍可在有效期内标注。图像和标注绑定到你冻结的那一帧，不在你拖框后偷偷换成新图。

## 一个批次超过16张时怎样标注

旧版本只返回最近12张，导致前面的照片没有网页入口；现已改为全部图片分页，不需要重新采集。

1. 到“本批次采集与历史标注”，在“标注批次”选择当前或历史批次。
2. 每页可选16／32／64张，用上一页、下一页或页码跳转访问全部照片。76张以每页16张显示为5页，第5页为第65–76张。
3. 优先选择“灯色筛选→只看待标注”，也可只看某一路相机。图片按采集先后排列，继续采集不会把前面页面的顺序挤走。
4. 图片下方选择灯色即保存；点击缩略图可以查看原图。“只看待标注”时，刚标好的图片会退出当前筛选，这是正常行为。
5. 点击“导出所选批次清单CSV”生成该批次当前标签清单。

切换标注批次只改变浏览列表，不改变实时采集的写入批次。重启程序会恢复上次采集批次与已有标签；主动点“新建场景批次”才建立新批次。原图和已保存的人工标签不会因翻页或重启而重置。

## 第一批建议采什么

先完成一小批可检查的数据，再决定是否扩大数量：

| 条件 | 建议安排 |
|---|---|
| 距离 | 2 m、1.5 m、1 m、0.75 m、0.5 m；安全可见的范围内，以实际尺量为准 |
| 灯色 | 每个摆位各采红、绿；实际装置有黄灯和全灭状态则一起采 |
| 角度 | 正对、稍偏左、稍偏右；不修改固定车载相机姿态 |
| 光照 | 先室内跑通，再采室外顺光、逆光、阴影；避免只采一种亮度 |
| 每组照片 | 每种状态先5–10张，微调位置和光照，避免大量完全重复图片 |
| 负样本 | 没有灯具的跑道、白纸、红绿物品、反光面、蓝门等，分批保存 |

这些距离与数量是采集建议，不是比赛新增规则。红绿灯停车区只有1 m，尤其要保留1 m附近和近距离的真实外观变化、灯体被裁切或强光过曝的样本。

## 真实红转绿序列

1. 选择20秒、目标3帧/秒/路，点“录制两路灯色变化”。
2. 触发实物灯具的光电传感器，记录真实倒计时和转绿。静态测试可按设备正常方式遮挡传感器，不必让车自动驶过。
3. 自动结束或点“结束序列”。连续帧统一为待标注，避免红转绿后仍继承红灯标签；可在完整批次列表中分页、筛选并逐张标注。
4. 多录几次真实随机时长，并改变光照。不能用固定等3秒或10秒代替绿灯识别。

保存的是带接收时间的JPEG帧序列，不是恒定帧率视频；实际频率受5G影响，两路不是硬件同步。相同像素在序列中仍保留时间记录，并标明重复，方便后续挑帧。

## 文件和后续用途

- `session.json`：批次信息与数据分组说明。
- `images/`：车端返回的JPEG原字节，未画检测框或文字。
- `labels/<样本ID>.json`：人工灯色、可选灯体框、场景条件、接收时间、相机身份、算法参考及画质指标。
- `events.jsonl`：采集／修改标签记录。
- `sequence-*.json`：序列参数、保存数量、结束原因。
- “导出清单CSV”生成当前标签的 `manifest.csv`。

目前车端相机采集配置为640×480，但现有HTTP原始预览实际返回 **480×360 JPEG**。工具保存并记录实际收到的分辨率，不能当成原生全分辨率录像。原预览接口没有给JPEG附精确采集ID，所以远端帧号只记作提示，不冒充该JPEG的精确时间戳。

这是采集数据，不是已经训练好的识别器。人工标签与算法预测分开，未框选图像只有状态标签；不能直接把红／黄／绿当作原项目四类YOLO模型的类别编号。后续训练应按整段序列和物理摆位分训练／验证集，不能把相邻帧随机分到两边。

若还没有真实灯具，可以先采背景负样本并验证保存流程；不要把手机上的灯图片或程序生成图当作已验证的比赛灯数据。
