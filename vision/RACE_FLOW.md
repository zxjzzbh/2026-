# 完整比赛流程（2026-10-13）

技术栈：Python、OpenCV、NumPy、原 HTTP 控制台及原生 HTML/CSS/JavaScript。复用 Pi 上已有双摄缓存、RasAdapter S3/S4 串口和已使用的 I2C 播报方式，无 ROS。只有一套总流程执行器持有串口，各比赛任务的单项测试仍保留；旧固定档短测、重复避障入口和标定表单已从网页移除。

## 2026-10-13 转向统一与页面精简

队员指定的 S3 端点统一为右 1350 μs、中位 1610 μs、左 1870 μs。遥控、分项循迹/避障、完整流程及执行限幅已对齐；S4 油门、刹车和 S1/S2 云台范围不变。端点是用户提供的输出参数，不代表已实测轮角。旧 1570/1650 的半径记录保留，但不用于新端点的米制规划；新半径字段为 `steering_radius_right_cm`、`steering_radius_left_cm`。

同一只已跟踪锥桶连续接近后进入近处、车侧或下沿裁切区时，保持低速向选定一侧避让，不再仅因像素位于近处或变成裁切形状就停车。近场延续只沿用短时间内的同一目标历史，不计算假造的车下距离；通过计数仍为视觉估计，进入过车身余量时会记录接触情况待复核。新出现、无法关联的前方障碍、无白线内通路、失联和急停仍会停止。

网页保留完整流程与发车、斑马线、红绿灯、锥桶、停车、缴费各任务入口，以及常用阈值/油门/转向调节。标定导入、几何/运动标定表单、旧固定档短测和重复避障入口已删除；标定文件和历史回放没有删除。当前仅改本地代码，未连接、烧录或部署车辆。

## 运行入口

1. **本地检查**：在仓库根目录双击 `check-race-flow.cmd`。只检查配置、运行软件测试，不连接小车、不打开摄像头或电调。
2. **以后部署到原网页**：车辆联网、结束所有控制会话且电调关闭后，手动双击 `update-race-flow.cmd`。默认私有连接资料仍从仓库旁的 `连接准备_20261009/smartcar-connection-handoff` 读取，不写入 Git。脚本会备份、测试、核对旧功能和参数、更新原服务；发现车端锥桶基线不同会停止，避免覆盖队友的新代码。
3. **比赛使用**：原遥控把车开到切换区并停稳。在原网页新增加的“完整比赛流程”面板点击“已在切换区停稳 · 进入自动模式（F/B）”。这一步结束原遥控会话并接管车辆，保持中位 3 秒后等待蓝色挡板。没有看到挡板，或只是图像中断，不会发车。
4. **停车缴费**：正确半区取得停稳反馈后，程序释放驱动输出，开始 30 秒窗口，并复用原缴费面板识别二维码。由队员微信支付 0.01 元，再点击总流程的“我已实际支付”记录结果。没有任何自动支付接口。
5. **退出/单测**：急停或退出总流程后，原发车、斑马线、红绿灯、锥桶、停车观察和缴费单项入口恢复。失联或画面中断后的恢复不会自动续跑。

软件检查命令：

```powershell
$env:PYTHONPATH = "$PWD\vision\src"
python vision/tools/race_flow.py check
python -m pytest vision/tests/test_race_flow.py vision/tests/test_parking_bay.py -q
```

车端新入口是 `vision/tools/serve_race_flow.py --race-live`，**必须沿用现有服务的其余摄像头、串口、斑马线和红绿灯参数**。部署脚本只替换入口并追加该开关；不要另开第二个摄像头/控制服务。省略 `--race-live` 时总流程启动按钮不可用。

## 任务顺序及与单测的区别

| 阶段 | 总流程行为 | 单项测试 |
|---|---|---|
| 手动切换 | 在切换区停稳后由人点击接管；只开一个执行器 | 原遥控操作不变 |
| 蓝色挡板 | 先连续确认存在，再连续确认两路均移开，进入斑马线阶段 | 原发车单测仍只播报 |
| 斑马线 | 沿用 65/50/25 cm 相机参考及保存的刹车触发点，停稳候选后保持 10 秒并播报队伍信息 | 原距离调节及单测不变 |
| 红绿灯 | 沿用双路同算法、2 秒窗口和共用红/绿比例；实际红灯停车后实际绿灯达标才衔接前进 | 原红绿灯单测仍“绿灯只播报” |
| 两桶避障 | 复用持续低速绕行、白线向内纠偏和视觉通过估计；证据不足结束本轮，不自动调用人工跳过按钮 | 原低速测试及人工确认按钮保留 |
| 停车 | 识别空闲半区，进入已有米制入位决策与执行桥；整车范围和持续停稳反馈成立才进入缴费 | 原停车单项仍可只观察，不开电机 |
| 缴费 | 入位停稳后启动 30 秒窗口，队员扫码并声明结果；不把声明当成银行到账验证 | 原独立缴费面板保留 |

本 PDF 的第 5 页写停 3 秒，而第 6 页注意事项及第 8 页罚则均写 10 秒。本版按后两处及队伍当前配置采用 **10 秒**。信号灯前的光电装置由赛场触发，程序不假设它已接入车上，也不以本地随机倒计时代替真实绿灯。

## 当前限制：停车执行尚不能视为已完成实车验收

现有停车代码缺少当前近场地面映射、识别验证、连续位姿、转向档位曲率与制动反馈的完整有效配置。本版已写好相机/世界坐标连接、入位决策和执行桥，但**默认配置下到停车入口会制动并明确提示缺项，不会强行盲走，也不会启动缴费计时**。可用已有实际记录补全对应配置，不要把 `null/false` 改成随意数字/`true` 只为了绕过检查。

停车使用 `parking-bay.local.json` 中已确认的映射和运动参数，及锥桶参数中的转向/光流验证数据。`ParkingWorldFeed` 只在这些条件具备时输出世界坐标；坐标跳变、画面丢失、新障碍或停稳证据不足会停止。两秒以内的近处车位边缘出画只有在已锁定静态布局和连续有效里程反馈时才可衔接；不是无限沿用旧图。

斑马线停止位置、红绿灯前轮位置、锥桶通过次数和整体完赛仍需实车验收。软件测试中使用的传感器序列仅用于验证逻辑，不是比赛视频或真实运行记录。

## 源码组成与参数

- `race_flow.py`：状态机、配置快照、各阶段输出衔接。
- `race_flow_camera.py`：读取现有相机缓存，复用斑马线、红绿灯、蓝桶和停车检测器。
- `race_flow_console.py`：遥控释放、单一串口所有者、心跳、急停、播报和缴费记录。
- `race_flow_controls.py`：原控制台上的总流程面板，不是模拟网页。
- `configs/race-flow.json`：全流程速度/转向及时间上限；现场可保存为同名 `.local.json`，部署保留。

进入总流程时读取原模块已保存参数，之后冻结本轮快照。全流程默认巡航 1600、慢速接近 1575、左 1870、右 1350、中位 1610/1500、有限 F/B 刹车 1400；不改变单项测试中的设置。车辆几何在总流程中统一引用既有锥桶/整车尺寸；已验证停车尺寸与车辆不一致时拒绝继续。

日志位于车端 `run/race-flow-<编号>/`，记录阶段、原因和控制意图，不写控制令牌或二维码付款内容。源码默认不自动运行、不开机发车、不自动上传或合并 GitHub。
