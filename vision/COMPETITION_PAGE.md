# 独立比赛操作页

入口：电脑 `http://127.0.0.1:8082/competition`；直连小车 `http://<car-address>:8080/competition`。
原 `/` 调试页保留，完整流程面板里也有新页链接。

仅显示四部分：

1. **遥控驾驶**：双摄实际原图、原键盘/屏幕/手柄控制、就绪确认和急停。沿用车端固定档位及F/B倒车限制，不开放PWM标定/分项按钮。
2. **手动切换**：遥控到切换区停稳，点“结束遥控，释放控制”；释放完成后点“已在切换区停稳 · 进入自动驾驶（F/B）”。进入后沿用原中位初始化与挡板等待。
3. **自动驾驶**：显示原完整流程当前阶段、指令、任务实际识别图，可结束自动返回遥控。仍使用原完整流程的停车就绪检查；新页面不把独立停车测试冒充已通过全流程停车验收。
4. **停车付款**：保留第二路二维码截图、放大/下载、手动30秒计时及付款声明。完整自动流程进入payment时，使用该流程的计时和付款声明按钮，避免重复启动独立计时。付款由队员在微信完成，本页不转账、不核验到账。

打开页面仅读取状态和画面，不准备或启动车辆。原单项任务占用控制时，本页不能发遥控指令；另一页面的自动流程仅能观察，不接管其心跳。显式急停仍可结束车辆控制。本页自己持有控制时，离开/失焦会停止；支付时不会自动重置原计时。

实现使用 Python HTTP 服务、原生 HTML/CSS/JavaScript，复用已安装的手动控制和付款客户端，仅增加页面布局及自动流程连接。与原页共享同一后台控制器、摄像头缓存、身份检查和控制期限，不启动第二个UART/摄像头进程。内部隐藏的PWM兼容节点只用于保持原客户端结构，不显示或开放调试入口。

仅增加页面时使用 `vision/tools/deploy_competition_page.py --apply`：核对空闲状态，对现有启动入口只加入页面包装，安装页面模块并运行检查。其余车端源码、参数和服务启动参数逐字节保护，包括本地尚未同步的队友算法更新；不使用旧算法覆盖车端。整栈同步仍可使用原部署工具，但需先正常对齐算法版本。页面本身不改变车辆运动算法或现有未完成的现场验证状态。

## 当前版本的斑马线短停

分项斑马线、命令行运行和完整流程均已接入首次识别短停：新鲜画面第一次识别出斑马线，立即发出原有有限 F/B 制动脉冲；运动反馈连续满足原停稳条件后，短停 **0.5 秒**，再按原参数继续接近原停车参考。每轮仅触发一次，原定点停车 **10 秒**及队伍播报保留。短停不播放原停车播报。

如果首次识别或短停滑行期间已经到达原刹车参考，直接完成原定点停车，不再额外向前启动。运动未知不会被当成停稳。原急停、画面过期及控制失联处理保持。停车区复用的制动核心默认不开启斑马线短停，不影响入位控制。

`stop_stage=first_detection` 表示首次短停，`original_operation` 表示原停车操作；分项日志保留短停和正式停车各自的证据帧。完整流程日志也保留对应输出字段和阶段原因。

这部分部署使用 `vision/tools/deploy_crosswalk_first_stop.py --apply`，直接改现有入口。对车端较新的完整流程仅修改斑马线控制器构造，不替换队友停车实现，不更改服务启动参数。
