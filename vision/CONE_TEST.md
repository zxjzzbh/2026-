## 固定档转向／刹车短测（不依赖尺寸、地面标定）

此独立入口用于获得运动标定数据，不要求先完成自动避障标定，不会自动把任何项目标记为“已实测”。原遥控 A/D 仍为 1750／1550 μs，与本入口的 1570／1650 区分。

1. 结束原遥控或红绿灯控制。电调关闭、保持 F/B，在锥桶面板点“准备短测”。
2. 默认短测油门 1575 μs、前进 0.8 秒；可调 1501–1625 μs、0.2–2.0 秒，只作用于短测，不改变遥控、红绿灯或自动避障参数。
3. 打开电调，现场确认静止、路线空旷且有人能立即断电，再选择一项：
   - **1570 固定转向短测**：S3 固定 1570 μs，低速前进画弧后刹车。
   - **1650 固定转向短测**：S3 固定 1650 μs，低速前进画弧后刹车。
   - **直行 → 刹车短测**：S3 回中 1610 μs，直行后刹车。
4. 每轮由车端独立进程执行：3 秒中位初始化 → 0.4 秒固定转向且电机中位 → 设定时长前进 → 1400 μs、每次 0.12 秒的 3 次制动（间隔至少 0.1 秒中位）→ 中位等待 0.5 秒 → S3 回中。固定转向会实际前进，不是仅原地摆舵。
5. 程序结束后先现场确认停稳，再点下一轮。完成测量后点“停止并结束短测”，释放串口，恢复原遥控和红绿灯入口。空格、Esc、原急停、失焦、失联、断帧同样会终止短测。

看门狗保持 0.2 秒指令租约，前进计时在车端独立进程内，心跳和重复点击不能延长本轮。一轮期间不能切换固定档；准备会话最多 3 分钟。网页显示的是控制指令，不是实际舵角或车速。

记录位于 `run/cone-short-时间/`：`events.jsonl` 包含本地单调时钟的前进／制动触发时间，阶段切换时保存两路缓存图及图像时间戳。图片不一定恰好对应制动瞬间，网页还有网络延迟，不能把网页文字变化当精确刹车起点；不自动给出未经测量的制动距离或半径。

## v2 网页运行顺序

1. 点“开始识别”检查实际双摄、白线和锥桶；标定齐全后，第二路会叠加紫色候选路径，页面显示行驶阶段、实测速度、位移与通过数量。没有标定时明确显示“待标定”。
2. 点“停止识别”，填写“现场尺寸”“避障速度与运动标定”，保存。转向继续限定 S3 1570–1650 μs，中位 1610 μs；输入两个端点实际转弯半径，左负右正，程序据此换算，不猜测转向方向。
3. 从“第二路地面标定导入”保存实测点。可参考 [JSON 模板](configs/cone-ground-template.json)，至少 4 个不共线拟合点及 2 个独立检查点。坐标原点为后轴中心，x 向右、y 向前；手机外观照片和斑马线触发位置均不能代替地面映射。
4. 地面映射录入后，保持电调关闭；先填写拟验证的光流误差上限和行程范围，不勾选“已核对”。点“开始识别”，手动推车，核对页面位移／转向与尺量是否一致；超过填写行程或失去有效地面特征会要求重新准备。确认误差范围后再保存“已核对”。光流失效不靠油门推算位移。
5. 现场测试：F/B 模式且电调关闭时点“准备避障”；软件会检查标定、左右白线及新鲜位移，再取得中位输出。随后打开电调，车辆静止、场地就绪后点“开始避障”。3 秒中位后低速绕行；通过两桶并回归赛道后制动停车。

新目标正在收集确认帧或暂时无通路时，先有限制动、保持中位等待；路径确认、取得静止反馈且完成刹车释放间隔后继续。连续 3 秒仍无通路则结束本轮。缺少白线、图像／光流失效、过速、页面心跳丢失、人工停止或总时限到达时，会关闭本轮输出，并复用现有有限 F/B 刹车保护。独立执行进程保持不超过 0.2 秒指令租约。避障占用控制权期间拒绝遥控、斑马线和红绿灯的其他驱动请求；结束后恢复原入口。没有自动接到红绿灯之后。

油门默认 1575 μs，可调 1501–1625 μs；速度上限默认 0.2 m/s、行驶时限 30 秒，是软件限制，并不代表已测得该油门对应的车速。实测超过速度上限会退出；初次现场须核对速度与制动距离。准备及开始不会由服务重启或刷新页面自动触发。

每次准备后在 `run/cone-drive-时间/` 保存生效配置、决策／输出日志及结束原因，供现场判断路线、制动和停止原因。软件测试通过不等于实车已经完成两桶任务。

网页入口沿用 `http://127.0.0.1:8082/`；部署后在红绿灯正下方显示“蓝色锥桶 · 独立测试”。原有遥控、斑马线、红绿灯源码及其现场参数受到部署脚本保护。

本赛道为两侧白线之间的红色塑胶直道：**整个车辆外廓及轮胎都必须留在白线内侧**。识别使用蓝色与轮廓判断锥桶、红色地面辅助判断场景。白线取靠近车道的一侧边缘，不用白线中心充当通行界限。缺少任意一侧边界或红色地面未确认时，网页明确显示边界未确认；不把 123 cm 平均换算成整张图片的像素比例。

新增圆顶／俯视圆形识别已用用户四张实物照片检查。俯视候选可以确认存在蓝色物体，但底部接地点不可靠时不用于米制投影。手机照片只用于外观检查，不用于标定车载摄像头的距离。


## 现场尺寸接口

在“蓝色锥桶 → 现场尺寸填写（cm）”核对预填尺寸，修改后点“保存全部参数”。先停止识别即可修改，无需操作电调或遥控准备按钮。

| 页面字段 | 含义 |
|---|---|
| 赛道可行驶宽度 | 两侧允许行驶边界之间的宽度 |
| 车辆最宽处 | 包括轮胎、外露结构 |
| 车长 | 最前端至最后端 |
| 后轴到车头 | 后轴中心至车头最前端 |
| 后悬长度 | 后轴中心至车尾最后端 |
| 锥桶高度 | 实物高度 |
| 锥桶底座宽／直径 | 取最大底座宽度 |
| 车身与障碍余量 | 在车身外额外保留的间隙 |

可先填部分项目，其余留空。后轴到车头加后悬应等于车长；超过 2 cm 不一致会提示核对。全部尺寸均有效时才记录“尺寸已填写”，但这不会把地面投影或运动标定标为完成。

网页输入单位是 **cm**，后台配置内部单位是 **m**。网页保存到同目录 `cone-trial.local.json`，不覆盖团队默认配置，也不进入 Git。命令行同样优先读取该本地文件。

API：沿用原控制台的同源校验和会话密钥，`POST /api/drive/cone_settings` 接受 `geometry_cm` 对象，其键如下。该接口数值单位为 **cm**，后台自动换算为米；`null` 表示待测。

```json
{
  "geometry_cm": {
    "lane_width": null,
    "vehicle_width": null,
    "vehicle_length": null,
    "rear_axle_to_front": null,
    "rear_overhang": null,
    "cone_height": null,
    "cone_base_width": null,
    "clearance": null
  }
}
```

保存尺寸不会发送 PWM。颜色阈值也在页面调整，默认蓝色 HSV 为 `[100,110,50]` 到 `[135,255,255]`，3 帧且至少 0.15 秒确认。红色地面辅助比例默认为 15%，可在网页调整；该比例是颜色像素证据阈值，不是通过距离或避障完成比例。室内非红地面不抑制蓝锥外观识别，只将跑道状态标为未确认。网页识别持续运行至点击“停止识别”，画面中断会等待恢复。

## 独立绕行逻辑与待接入内容

`cone_planning.py` 使用后轴中心为原点、x 向右、y 向前的米制坐标。选择候选绕行方向时同时考虑两桶；近邻锥桶的绕行区间重叠时不能突然反向变道。路径采用平滑曲线，并以整个带余量的车身矩形检查锥桶与边界。

`ConeMission` 输出循迹、绕行、回归、完成、等待反馈或停车意图。`ConeNavigator` 将第二路画面、实测投影、地面光流、白线内侧与物体跟踪接到该状态机；`ConeDrivingController` 把可通过路线换成实测映射内的转向指令；`ConeRun` 管理控制权、F/B 执行器、页面租约和退出。没有可通过路线、观测过期、位姿缺失或障碍不明确时停车。只有从“曾在车前”到“已在车尾之后”的实测位姿关系满足条件，才累计已通过锥桶；已建图目标短暂消失时由可信位姿维持位置，同一位置重新获得跟踪 ID 不直接累计第二只。

还需现场完成：

1. 固定第二路摄像头姿态，标定地面像素到米制坐标与有效视野，检查独立点误差。切勿复用斑马线的单个距离触发点。
2. 确认真实赛道边界能被持续识别。目前白线检测是图像空间基线；候选规划器接收局部直线走廊，不能直接用它承诺弯道通过。
3. 测量转向能力、低速实际速度及制动距离，并验证已接入的第二路地面光流反馈。当前配置中的 `ground`、`motion`、`driving` 提供这些接口，尚未填写的值继续保持空白。

只填写车宽和锥桶尺寸仍不足以确定方向舵机应输出多少，或车尾是否已经越过锥桶。现有遥控和 F/B 刹车参数没有被本模块修改。

米制准备检查：

```powershell
.\.venv\Scripts\python.exe vision/tools/cone_trial.py check
```

规划器回放入口为 `cone_trial.py replay --input 实测观测.jsonl`，每行包含 `now_s` 和 `sample`。sample 接口包括 `frame_id`、`captured_s`、有效的 `pose`、稳定世界坐标 `observed_world`、`lane_bounds_m`、`lane_valid`、`coverage_forward_m`、`lane_offset_m` 和 `unresolved_obstacles`。时间必须来自同一单调时钟；该入口只写决策日志，不驱动车辆。

## 原控制台接入

车端在现有启动参数基础上增加：

```text
--cone-config /home/pi/smartcar-race-20261002/vision/configs/cone-trial.json
```

需要同时存在现有 `--brake-config` 与 `--traffic-config`。部署工具为 `tools/deploy_cone_trial.py --handoff 现有交接目录`，复用已有凭据与严格主机密钥校验；先备份并进行车端回归检查，确认控制会话未启用后再重启服务，失败则恢复。只更新新增锥桶模块及启动器；不能用仓库中的旧 `serve_boot_test.py`、`manual_controls.py` 覆盖当前车端版本。

源码：`cone_vision.py`（识别）、`cone_planning.py`（规划／状态机）、`cone_navigation.py`（位移／路径跟随）、`cone_execution.py`（实车会话）、`cone_observer.py`（缓存和运行整合）、`cone_controls.py`（页面）、`tools/cone_trial.py`（独立观察入口）。

验证包含仓库实拍图片、空场背景、近距离和贴边目标、重复帧、两桶几何路径、整车通过条件、尺寸保存及原控制台组合。单元测试中的几何数字只用于测试，不是实车参数，也不代表真实避障通过。
