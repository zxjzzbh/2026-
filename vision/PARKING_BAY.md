## 原网页操作

部署成功后，在原网页打开 `http://127.0.0.1:8082/#parking-trial-test`，刷新到带有“低速停车入位”区块的版本。

1. **结束其他行驶任务。** 停止遥控、斑马线、红绿灯、锥桶或完整流程，释放车辆控制权。停车识别可以单独运行。
2. **检查画面和方向。** 让第二路 H65 看到停车黄线、蓝挡板和空闲半区，点击“开始停车区识别”。网页始终给出暂定或已确认的左／右建议；核对目标是否合理。
3. **电调关闭且处于 F/B 挡，点击“准备停车（电调关闭、F/B）”。** 油门在准备时固定，选侧会在开始前结合最新有效画面更新。默认油门为 **1575 μs**，需要时在准备前修改；准备期间保持中位。
4. **打开电调、保持车辆静止，场地就绪后点击“开始低速入位”。** 程序先保持中位 **3 秒**，随后按已选侧低速接近，不要求完整车位框。看到挡板时持续以其旁边空位为目标调整方向，对齐后回正；只有当前方向证据完全缺失时才使用短时轻转后直行的退化策略。真实车位几何出现后直接接入比例转向，不重新等待或停车。开始行驶后不再自动跨侧切换。
5. **观察自动刹停。** 远端黄线到达既有 50 cm 图像参考时发出有限 F/B 制动，再通过图像运动判断停稳。近入口线移出画面后会继续匹配实际远黄线和侧线，不把近线消失直接当成完成入位。
6. 随时可按 **空格、Esc** 或点击“停止入位／结束本轮”。页面心跳失效、断流、所选侧实际挡板仍会中止本项；缺少完整框本身不再触发停车。完成后实测车辆位置，再判断是否符合停车要求。

开始后的 3 秒用于中位初始化，不是停车区内的付款倒计时。本项结束不会自动开始付款、声称到账或确认比赛完成。

## 当前选区建议怎么理解

观察程序持续输出方向，避免在证据不完整时整个建议栏空白：

- 看到一侧蓝挡板，优先建议另一侧；只有一侧可见空闲时，采用该侧作为候选。
- 当前证据不足时保留有依据的历史方向，并明确标为暂定。
- 尚无任何有效方向证据时，明确显示**默认暂选右侧**，不把默认值写成识别结果。
- “一侧入口遮挡、另一侧可见空闲”在至少 3 个新帧、连续约 0.5 秒成立后，才显示视觉已确认；重复帧、过期帧不能累积确认。

暂定方向和视觉确认都不等于已确认可通行。独立入位试验在开始前采用最新新鲜的有效选侧证据，没有新证据时保留准备侧；开始后锁定本轮目标。若目标侧实际上被挡住，不会因默认方向而直接驶入。蓝块下方需有可见红／绿地面才作为停车挡板方向提示，防止抬头拍到衣服和柜子时误判；不要求地面出现完整黄线框。

## 停车结构与实拍识别

停车区沿前进方向长 **1 m**，沿中线分为左右并排半区。左／右均按车上前进方向定义。近远两条黄横线、黄色纵向分隔线及外侧黄线或白色跑道边线共同提供结构证据。

此前实拍漏检有三个原因：H65 将浅黄胶带拍成低饱和度颜色，旧阈值只保留了整图 34 个黄色像素；蓝挡板遮住左半区边界，旧算法要求两个完整封闭框；旧空闲判断只认可红地面，排除了当前室内绿地面。

现已加入受结构约束的浅黄兼容范围，并支持“自动／室外红色跑道／室内绿色地面”。网页“识别参数”可以修改地面类型、赛道总宽、入口蓝色占比和可见地面占比；缺少 `surface` 的旧配置默认自动。保存不会把任何标定验证标志自动改真。

一个半区可见且相邻蓝挡板与入口对齐时，可以输出遮挡侧和可见侧的视觉候选。隐藏侧的 `corners_px`、`polygon_m` 保持 `null`，`layout_complete=false`、`metric_geometry=false`、`occupancy_verified=false`；不镜像补造隐藏车位。实际浅黄胶带＋绿地面＋左挡板图片及其左右翻转已纳入回归。

## 独立低速入位如何工作

`ParkingEntryController` 使用第二路 **480×360 实际像素**。无完整四边形时进入 `seek`：持续采用本轮低速油门；有实时挡板时，以其相反侧的目标像素相对车身图像中心的误差持续转向，随目标对齐逐渐回正，保留1350/1610/1870端点和变化速率限制。只剩默认/历史方向时，起步约1.2秒有限轻转后回中；不会把一直可见的挡板也按1.2秒定时清掉。已看见车位短时漏框先保留方向，再采用当前挡板或直行寻找；不伪造缺失远线。实际四边形恢复后当帧衔接比例引导；寻位不代表已确认整条通路安全或已经进入停车区。

右挡板的本次实拍中，停车框面积不足旧图像2%阈值，胶带饱和度低且绿地面反光被宽松白色阈值混入。新增局部对比度候选，只在已见挡板相反侧查找真实地面组件，要求四条边均有亮标线支持、内部可见地面且无蓝色遮挡；裁剪边界不能充当停车线。这类小目标输出为未验证的 `entry_candidates`，不补造另一个半区或米制位置。

入口近线驶到车下、退出画面后，`parking_guidance.py` 从真实地面组件提取由远黄横线和两侧边线围成的可见区域；控制器通过已锁定远端两点的连续匹配选取唯一引导区。远端黄线完全不可见时无法据此判断已经入位，页面会显示仍在寻位；不会凭默认方向报告成功。

ROI 底部截面只是引导截面，始终标为 `near_boundary_observed=false`，不会冒充停车入口。引导区的远边必须有实际黄线支持、两侧必须有实际黄／白线支持；图像边框、黑底或蓝色遮挡不能替代空闲车位。控制器不通过计时凭空延长不存在的边界。

制动复用第二路此前保存的 **65／50／25 cm 图像参考**，其中 50 cm 对应行被迁移为本试验的远黄线触发参考。已有约 17 cm 制动距离只作为历史经验，不能保证本轮刹车距离相同；图像行也不是重新测得的停车距离。历史地面映射用于图像中心线参考，不被升级为当前米制位姿。

试验复用 F/B 有限制动和图像运动停稳判断，最终状态仍标记 `field_verified=false`、`physical_stop_verified=false`、`whole_vehicle_inside_verified=false`、`reference_transfer_verified=false`。不会输出伪造的米制位置或将光流停稳当成四轮已经入位。

| 参数 | 当前用法 |
| --- | --- |
| 前进油门 | 默认 1575 μs，可调 1501–1625 μs；下次准备时生效 |
| 转向 | 右端 1350 μs，中位 1610 μs，左端 1870 μs；过程平滑调整 |
| 电调 | F/B；中位 1500 μs，制动 1400 μs 的有限脉冲 |
| 车身尺寸 | 车宽 29.5 cm、后轴至车头 33.5 cm、后悬 8.5 cm，合计长度 42 cm |
| 车位长度 | 1 m；入位试验采用当前锥桶模块保存的实车几何与赛道宽度，读取时复制为本轮快照 |
| 历史参数 | 继续使用已有相机参考和现场参数，不新增或伪造物理标定 |

仓库基础停车配置曾记录总宽 123 cm，用户后续实测白线内宽为 125 cm；网页显示的是当前生效配置，不能把旧基础值误称为最新实测。2 cm 余量等软件限制也不是测得的硬件精度。

## 软件组成与日志

Python + OpenCV + NumPy，复用原 HTTP 服务及原生 HTML/CSS/JavaScript，无 ROS 或新学习模型依赖。

- `src/carvision/parking_bay.py`：黄线、地面、入口挡板及视觉结构候选。
- `src/carvision/parking_bay_console.py`：第二路缓存、暂定／确认选区、识别记录，以及独立入位会话接入。
- `src/carvision/parking_bay_controls.py`：原网页识别与低速入位按钮、油门调节、互斥控制和急停。
- `src/carvision/parking_entry.py`：纯计算的图像引导入位控制器，使用历史参考及有限制动。
- `src/carvision/parking_entry_run.py`：显式准备／开始、车辆输出租约、会话心跳和结束处理。
- `src/carvision/parking_guidance.py`：近线出画后的实际远黄线与侧线引导。
- `src/carvision/parking_mission.py`：完整流程使用的严格米制入位决策。

现场识别配置保存在 `vision/configs/parking-bay.local.json`，优先于 `parking-bay.json`。每轮独立入位冻结当轮参数；不覆盖原遥控、红绿灯、锥桶或缴费设置。

观察日志位于车端 `run/parking-bay-<编号>/`；低速入位日志位于 `run/parking-entry-<编号>/`，包括当轮参数、决策和结束摘要。后续分析应区分“方向建议”“实际前进输出”“制动触发”“视觉停稳”四件事。现场图片可能包含付款码，不批量提交原始日志到 Git。

## 完整流程的米制入位契约

本节描述 `ParkingMission`、完整比赛流程及新增独立路径入库；不是原视觉对照试验的启动条件。

`ParkingMission.step(sample, now)` 接收同一主机单调时钟下的新鲜观测，要求：

- 递增的 `frame_id`、`captured_s`，以及固定 `coordinate_frame="parking_road_world"`。
- 后轴中心的持续位姿 `x_m/y_m/yaw_rad`、误差上限、时间和实际验证标记。
- 真实 `speed_mps` 与当前路径可见性；不能用油门脉宽推定速度。
- 两半区的真实 `polygon_m`、占用状态和经过验证的 `occupancy_verified`。

坐标不能随每帧相机移动。新鲜的非米制／部分布局会清掉旧米制缓存，随后漏检不能重新恢复此前的“空闲”结果。默认缺失的有效标定、连续位姿或占用反馈依然阻止完整流程自动入位。

米制规划校核整车扫过范围、外侧边界、分隔线和转弯曲率，并结合实测制动距离安排减速。正确半区内的整车外廓、速度和持续停稳条件成立后才输出 `parked`／`payment_ready`。输出仍是供执行桥使用的决策意图；`payment_ready` 不等于付款到账或裁判验收。

## 本地检查和回放

本版全套 **1522 项通过、3 项跳过**。新增覆盖实际浅黄／绿地面／挡板识别、持续方向建议、前端交互、独立输出会话、近线出画几何续接、有限制动、停稳和失效退出；软件回归不代替实车停车验收。

在已配置项目 Python 环境的根目录运行，命令只做本地测试：

```powershell
$env:PYTHONPATH = "$PWD\vision\src"
python -m pytest vision/tests/test_parking_bay.py vision/tests/test_parking_guidance.py vision/tests/test_parking_entry.py vision/tests/test_parking_entry_run.py -q
```

单张第二路 480×360 实拍图像检查：

```powershell
python vision/tools/parking_bay.py image --input "实际图片.jpg" --output "run/parking-check-new"
```

严格米制决策的离线回放：

```powershell
python vision/tools/parking_bay.py --config "vision/configs/parking-bay.local.json" decide --input "观测.jsonl" --output "run/parking-decisions-new.jsonl"
```

回放每条输入包含 `now_s`。它不会给硬件发送动作，缺少严格米制数据时仍保持等待。更新入口 `update-parking-bay.cmd` 会连接车端并更新服务，不属于本地检查；本次是否部署完成，以实际部署结果为准。
