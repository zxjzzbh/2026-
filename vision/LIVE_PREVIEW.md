# 在电脑浏览器看树莓派真实摄像头识别

本版本新增 `serve` 命令。摄像头接在树莓派，采集与识别在树莓派执行，电脑用浏览器看结果。无需图形桌面、VNC 或 X11，Lite 系统也可使用。不会生成演示画面或自动保存录像。

## 给部署同学的操作

1. 将新版交付包解压到独立目录，保留原有配置与数据。更新树莓派上的视觉源码；确认 `python -m carvision serve --help` 能显示帮助。若找不到 serve，说明还在使用旧代码或旧环境。
2. 确认 USB 摄像头实际采集编号，停止其他占用同一摄像头的录制/图传程序。不能将 Windows 的 1401 搬到 Linux。
3. 在树莓派的 `vision` 目录启动。下面假设虚拟环境名为 `.venv`、目标相机编号已确认为 0：

```bash
.venv/bin/python -m carvision serve --camera 0 --host 0.0.0.0 --port 8080
```

4. 在树莓派执行 `hostname -I` 获取局域网 IP。电脑与树莓派接入可互通的同一网络，在电脑浏览器打开 `http://树莓派实际IP:8080`。
5. 页面应先显示“等待摄像头首帧”，随后显示实际画面。相机初始化可能需要等待；出错信息会显示在页面上。
6. 在启动程序的终端按 Ctrl+C，停止服务并结束采集。

`0.0.0.0` 是服务监听地址，不是电脑浏览器访问的地址。使用实际 IP，不要照抄一个示例 IP。

## 页面上看什么

- **识别叠加画面**：实际图像上的左右边界、中心路径、预瞄点和已启用的目标框。
- **原始画面**：同一摄像头的原始视图。
- **白线提取结果**：当前帧的白线候选掩膜，用于检查阴影、反光等干扰。
- 道路有效状态、归一化偏差、本帧计算耗时、预览更新速度、模型状态、源帧编号。

同一采集/识别进程服务所有浏览器，慢客户端不会排队拖住采集。默认预览上限 10 FPS、显示宽度不超过 960，缩小仅用于网络预览，检测仍使用原始输入图像；这不是实际性能承诺。网页速度还受 Pi 算力、无线网络和浏览器影响。

相机断开/处理失败时显示错误并隐藏画面；结果超过默认 1500 ms 未保持新鲜时标记超时，不把旧图当作实时图。网页显示的主机帧年龄不包括摄像头内部和完整网络显示延迟，不能作为端到端延迟。

## 参数示例

仅在确认摄像头模式有效后请求 720p/30：

```bash
.venv/bin/python -m carvision serve --camera 0 --host 0.0.0.0 --port 8080 --width 1280 --height 720 --fps 30 --preview-fps 10
```

训练出真实比赛四类权重后，用 `--weights 实际模型路径 --device cpu` 加载；没有权重时保持 disabled。当前没有比赛模型，先看基础循迹。看到画面不等于所有比赛元素已经能识别。

如果端口已占用，可换 `--port 8081`，浏览器也改成 8081。设备之间不通时检查 IP、同网互通条件和防火墙；不要通过重刷系统解决普通网络问题。

该入口用于可信局域网调试，无登录/公网部署功能；不要用于公网端口转发。它也尚未与团队 5G 图传模块统一共享采集源。
