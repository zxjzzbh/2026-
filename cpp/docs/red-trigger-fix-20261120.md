# 传感器触发后亮红灯漏识别修复

样本来自 cpp-1795153203834636914-jb_9fm_d 的实际行车录像，不是车辆停下后的网页画面。用户说明：经过灯前约 1 米的外部传感器后，红灯点亮；用户明确确认 secondary 视频帧1642是亮红灯。

红灯点亮前后三帧1640、1641、1642的时间为385.695、385.895、386.031秒。红、黄灯罩V中位数均约250~252，旧亮度差条件没有通过。亮红灯灯芯的饱和度下降，呈明亮粉红，和同帧未通电黄色灯罩的色度关系改变。

新红灯候选路径保留完整灯架和三灯位置证据，要求红灯半径至少6像素、V>=200、灯芯对外环亮度差>=35、红色占比>=60%；同时至少35%的灯芯像素为H>=165、35<=S<=125、V>=200的明亮低饱和红，红灯S中位数不超过同帧黄色灯罩的1.05倍，黄/绿灯位置颜色支持各>=50%。它补充已有普通红灯、白芯强光红灯路径，不以“亮度下降”作为红灯判据。

原实车处理帧间隔中位约0.164秒、90分位约0.200秒，旧0.15秒间隔无法可靠累计。现在仍需同摄像头、同灯架三个不同且新鲜帧，最大间隔0.25秒、总跨度0.5秒、单帧最大年龄0.25秒。只放宽三帧总跨度，未允许超过0.25秒的旧图参与确认。

对本轮142帧辅摄接近录像，按原日志的捕获和决策时间回放，新版在帧1642首次产生 stop=1，原因confirmed_current_red；原版该片段没有红灯停车请求。首次候选至确认约0.336秒，不包含全部实车制动距离。此前明确标注全灭的158组双摄观测回放未产生红灯、停车或绿灯许可。新增三张真实触发红灯图片进入测试资产。

25秒未确认转避障仍保留用户之前要求；这轮红灯在超时前已经点亮，修复针对超时前的真实漏识别。已确认红/黄灯停车后仍只能由可信绿灯释放。扩展板语音、斑马线10秒含播报、巡线、绕桶和停车算法不在本次改动范围。

以上是针对已标注开发样本的修复和回放验证，不代表任意光照均已通过实车验收。需要现场复测从触发红灯到实际停车的距离。
