| C | 见过绿灯后熄灯画面仍保留放行状态 | **已给出方案，待全量构建/实车验证** | 根因在识别器 `TrafficLight` 的 `GREEN_CONFIRMED = COOLDOWN` 锁存与 `main` 用 `state==GREEN_CONFIRMED` 派生 `o.green`。整改：`main` 改用"当前帧 `action==GREEN_GO`"作为放行依据，或识别器在新鲜帧未见绿时撤销 `GREEN_CONFIRMED`。该改动在 OpenCV 侧，本机无法编译，故未盲改。详见下方步骤。 |

| F | 锁定车位后长时间无观测仍继续前进 | **已修复（离线回归通过）** | 控制器限制"历史车位"可用时长（常量 `kBayMemoryLimitS = 8.0s`）：车位观测丢失且超过该时限即停车等待重新定位，不再盲目前冲。 |
| G | 选定车位被挡仍报告完成 | **已修复（离线回归通过）** | `ParkingHold` 增加复核：当前观测显示所选半区被挡时，不再判定完成，保持中性并给出原因。 |

## A / B / D / F / G 的关键实现（已通过单测）

- 事件号：`transition()` 进入 `ZebraBrake / TrafficBrake / ParkingBrake` 时 `brake_event_id_ = ++brake_event_seq_`，
  所有 `throttle_us = brake_us` 处都带上 `q.brake_event_id`。离开制动阶段自动清零。
  - 执行器保证：事件号严格递增才入队（同一脉冲重复帧不会再入队→不延长制动）；
    脉冲满 `brake_s` 后写中性并回报完成。
- 首帧时刻：`update()` 中 `if (last_time_ < 0) entered_ = o.time;`。
- 斑马线锁存：`ZebraApproach` 中用 `zebra_seen_/zebra_y_` 锁存并 `zebra_y_ -= forward_delta` 递推。
- 车位记忆时限：`parking()` 中记录 `last_bay_time_`，超过 `kBayMemoryLimitS` 停车等待。

## C / E 的建议改法与验收（需在树莓派全量构建后执行）

### C（熄灯后不应保留放行）
- 方案一（推荐，仅改 `main.cpp`）：`o.green` 只取"当前帧的 `TrafficLightAction::GREEN_GO`"，
  不再用锁存的 `state==GREEN_CONFIRMED`。
- 方案二（改识别器）：新鲜帧未见绿色灯泡时清 `GREEN_CONFIRMED`，仅当当前帧仍有合格绿灯才保持放行。
- 验收：回放"红→短绿→熄灭"与正常红绿序列：熄灯后不得放行；红停绿行正常工作；红绿冲突以红为准。

### E（过期画面不得恢复给油）
- 改 `Actuator::submit` 接受采集时刻 `captureTime`；`main` 在**实车路径**（`video.empty()`）传入
  `monotonic()` 采集时刻，`OutputPolicy` 用 `now - captureTime` 判定过期并保持中性。
- 仅实车路径启用（回放用视频时间，避免被误判过期）。
- 验收：软件注入 1.25s 延迟后，迟到旧帧到达时保持中位，直到新鲜有效画面到达。
  车端另测满负载时从采集到决策的实际端到端延迟。

## 仍需现场验证（决定能否完赛，不可省略）

1. 树莓派上 `bash build.sh`（编译 + 离线回归，本机仅验证了控制器子集）。
2. `bash run_debug.sh observe --show` 只观察不发车，确认双摄在线、时序正常。
3. 实车分项：撤板发车、斑马线车头距横道边缘 <30cm 且停稳 10s（含完整中文播报）、
   红停绿行与绿灯抵达、两个锥桶绕行、四轮入空位且左侧被挡时不误报完成。
4. 实车制动：前进档 1570µs 的实测制动距离、红/斑马线停车点是否在传感器与障碍之间。
5. 整场计时与判罚按《赛项二补充细则》第 5 页（前轮压起点线起算）用裁判计时核对。
