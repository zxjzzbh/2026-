# 全灭误判修复（2026-11-20）

现场用户确认整组灯全灭，原实车日志却在 frame=1160 进入等待绿灯，red=0、signal_stop=1。日志未记录具体原始候选，不能据此断言当帧是哪一盏灯误判。

当前位置主、辅摄原图均能找到真实灯架。主摄未通电红、黄灯罩的核心亮度中位数均约254.5，属于阳光下亮灯证据不明确，不能把颜色直接等同于通电。原录像另有围栏反光和天空被配成假绿灯的现象。

本版修改：

- 完整三灯几何需要各灯自身的形状证据；白色反光不能自动补成第三个灯。
- 普通候选增加共有暗色/灰色灯壳支持；保留原有强光红灯恢复专用路径。
- 同一相机、同一灯架的红/黄证据需连续三个不同且新鲜的帧确认，再触发锁定停车。重复帧、跨相机拼帧及过期帧不计数。
- 未确认的瞬时红/黄仍撤销绿灯许可，但不建立永久停车事务、不固定停止灯架，也不启动后续红候选超时停车。
- 已确认红/黄仍锁定停车；画面变暗、丢失或全灭不会自动放行，仍需同灯架新鲜绿灯窗口确认。
- 日志增加 signal_stop_reason 和 signal_observation，记录停车证据、双摄原始分类、各灯亮度及连续确认帧数，便于区分红灯停车、黄灯停车、候选超时和其他阶段故障。

默认10Hz时确认约需0.2秒，最慢允许相邻帧间隔0.15秒；这会引入确认延迟，现场需在足够制动余量处触发。未改变前进PWM、舵机、巡线、停车标定或相机的持久曝光设置。自动曝光已恢复原值。

离线检查覆盖当前全灭原图、反光假灯架、真实颜色合成图、瞬时误判、重复/过期/双摄帧、红黄停止和同灯架绿灯放行。合成亮灯图不代表实车通电灯验收；阳光已使未通电红黄灯罩接近饱和，必须用同位置实际通电红/绿灯再次验证可分辨性。
