## 三、本次在代码上修了什么（“能完赛”相关的关键点）

1. **修复“绿灯抵达即卡死”**（`src/controller.cpp` `Stage::TrafficApproach`）
   - 原逻辑：交通接近阶段**只在判到红灯时**才离开，进入制动→等绿灯→锥桶。
     红绿灯检测器必须先“跟踪到红灯灯罩”才可能判绿灯。于是当车辆在**红→绿之后才到达**红灯区，
     既判不到“红”也判不到“绿”，车会沿中线一直开下去，**永远到不了锥桶与停车区 → 无法完赛**。
   - 修复：新增“见到绿灯”或“在本阶段停留超过 `traffic_max_approach_s`（默认 25 s）仍未见红灯”
     即进入锥桶/停车阶段。红灯正常出现时仍第一时间停车等待绿灯，行为不变；只有“永不红”时安全退出。
   - 新增回归用例 `tests/test_controller.cpp`：`never-red traffic approach must eventually advance`。

2. **播报更可靠**（`src/main.cpp` `speak()`）：先 `espeak-ng`，再降级 `espeak`，避免缺一个合成器就“未播报”+10 s。

3. **成绩自检日志**（`src/main.cpp`）：运行结束时打印并写入 `summary`：
   `run_time` / `red_wait` / `valid_time_estimate`，便于按细则核对有效时间。

4. 新增配置项 `traffic_max_approach_s`（默认 25 s，`config/race.json` 可改）。

> 运动逻辑改动严格约束在“疏通流程”范围内，没有改动已调好的巡线/选边/停车几何。
> 仍须现场试车验证（见§7）。

## 五、红绿灯“停在哪”的取舍（重要，务必现场确认）

补充细则要求停在“传感器与红绿灯之间、传感器离灯约 1 m”的区域，判罚：
**未在区域停车 +20 s；抢灯 +20 s 且不扣该次红灯等待；未停车 +50 s。**

- 本工程策略：**判到红灯立即制动**（最稳妥地“不抢灯、不漏停”）。
- 代价：若相机很远就能看到红灯，可能停得偏早，落在区域外 → +20 s（但仍能继续完赛，损失可控）。
- 现场确认：用 `run_debug.sh observe --show` 观察“红灯被确认那一刻车距灯多远”。
  - 若**明显早停**：可缩小红绿灯 ROI（`roi_y_ratio_start/end`）或提高 `red_area_min`，让灯“够近”才确认；
  - 若**到线才识别、来不及**：反向放宽。
- 不建议改成“靠测距逼近再停”：没有可靠测灯距离时，误判会导致抢灯(+20 s 且罚更重)或不停(+50 s)，反而更差。

## 六、编译 / 离线验证 / 运行（在树莓派上）

```bash
cd /home/pi/<放本工程的位置>
# 依赖（一般已装 OpenCV4；语音用 espeak-ng）
sudo apt install -y libopencv-dev espeak-ng

# 1) 编译 + 跑全部离线回归（不含相机，不发车）
bash build.sh            # 内部：cmake 配置→编译→ctest，应全绿

# 2) 只观察，不输出执行器（沙盘/录像均可）
bash run_debug.sh observe --show
bash run_debug.sh zebra   --video /path/to/secondary.avi --show
bash run_debug.sh parking --video /path/to/secondary.avi --show
```

比赛（现场由人监管，切换区停稳、原遥控已释放后再发车）：

```bash
# 先在切换区停稳并完成交接；--handoff-complete 是操作员声明，不会替你停旧服务
bash run_race.sh --drive --supervised --handoff-complete
```

> 默认不写执行器；`--drive` 才会用 S3 转向/S4 电调。`--supervised`、`--handoff-complete` 是硬性门槛。

## 七、判罚规避 checklist（赛前 10 分钟）

1. [ ] `bash build.sh` 全绿（含新增的红绿灯退出用例）。
2. [ ] `announcement_text` = 真实“学校+队名”，`espeak-ng` 有声。
3. [ ] 起步：车在切换区停稳；日志出现 `wait_board`；移走蓝挡板后进入 `zebra_approach`。
4. [ ] 斑马线：停稳 10 s（日志 `zebra_hold`）、播报一次、停距 <30 cm。
5. [ ] 红绿灯：红灯在**规定区域**停、绿灯走；用 `observe --show` 确认停点远近可接受。
6. [ ] 双锥桶：先上后下都能绕过、不压线、不撞桶（撞桶 +20 s、拖行>2 m 判失败）。
7. [ ] 停车：选“未遮挡”半区、四轮全进、撞挡板会 +100 s，宁稳勿冲。
8. [ ] 结束 30 s 内手机扫码付 0.01 元并向裁判展示。
9. [ ] 全程不遥控、不写死路线；切换后拆天线、关遥控链路。
10. [ ] 拔网线/Ctrl+C 车立即停（信号处理已接管，执行器回中位）。

## 八、安全与协作约定（沿用工作区 AGENTS.md）

- 试车必须由**用户在场监管**；读状态、看日志、离线验证、部署本身都不代表授权发车。
- 服务正在控车时不重启、不自动准备/发车；正常前进输出不低于 1570 µs（1500 中位、1400 制动不属于前进）。
- 斑马线停车 10 s 是硬指标；室外白线间距按 117 cm（本工程 `lane_width_m=1.17`）。
- 代码包与录像重算只代表离线判断，**不能替代实车验证**；`VALIDATION` 未实测的动态误差需现场确认。
