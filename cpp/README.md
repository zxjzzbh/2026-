# car.zip — 2026 规则修订版

这是针对用户提供 `car.zip` 的独立 C++ 修订工程，版本 `car-2026-rules-20261118`。
接入 `红绿灯识别demo.zip` 的检测思路与现有第二路相机标定；没有把它覆盖到现有 Python 比赛/网页系统。
本版本只在电脑完成开发、编译和离线验证，未连接、部署或启动车辆。软件检查通过不代表实车已完成任务。

## 配合《赛项二补充细则》（本次 r2 修订）

详细逐条对照与现场操作见 **`docs/竞赛合规与现场操作.md`**。要点：

> 针对《室外5G无人车_R2代码复核交付报告_20261118》的逐条整改与验收见
> **`docs/复核整改-R2-20261119.md`**（制动事件号、无灯不判成功、斑马线锁存制动、
> 车位记忆时限、被挡车位不误报等已在控制器离线回归中通过）。

- **修复“绿灯抵达即卡死”**：交通接近阶段原先只在判到红灯时才离开，若车辆在红→绿之后才到达，
  会沿中线空转、永远到不了锥桶/停车区。现在“见到绿灯”或“停留超过 `traffic_max_approach_s`（默认 25 s）
  仍未见红灯”即进入后续阶段，红灯正常出现时行为不变。新增回归用例。
- 斑马线停 10 s + 播报（`announcement_text` 改成真实学校+队名；`speak()` 增加 espeak 降级）。
- 新增 `runs/<id>/telemetry.jsonl` 末行 `summary`：`run_time` / `red_wait` / `valid_time_estimate`，便于核对有效时间。
- 新增配置项 `traffic_max_approach_s`（`config/race.json`）。

## 已改什么

- 比赛流程：交接后等待蓝挡板确实出现再撤离 → 巡线 → 斑马线 → 红绿灯 → 两个锥桶 → 空闲半区停车。
- 删除按累计秒数开启斑马线、固定左右变道、6 秒重置/7.1 秒退出矛盾、跳过避障、单桶固定左转、A/B 字母停车路径。
- 斑马线停车 10 秒从地面视觉停稳证据起计，并播报当前配置的学校队名；不是制动开始后直接计时。
- 红灯 2 个新帧确认，立即请求 1400 μs / 350 ms 制动；绿灯须同灯组连续确认，不凭红灯消失或绿色背景放行。
- 图像采集时间与控制决策时间分开，避免处理耗时吃掉制动时长；主摄独立采集。绿灯确认可以跨越制动阶段，但断流后必须重新确认，不能拿断流前的绿灯继续放行。
- 双桶分别跟踪，按左右可通行空间选择方向；空间差小于 20 cm 优先右侧，但不越过车辆宽度约束；右侧空间小于 50 cm 且左侧可通行时优先左侧。转向变化限速，绕桶增益 1.35，普通巡线 1.0。
- 桶消失不直接判通过，结合真实运动估计更新目标；车尾通过后回中，可在第二个近桶出现时提前交接目标，避免等完全回中才开始第二次绕行。
- 停车通过黄色边线、白色外边线和蓝挡板确定目标半区，入口只用于进度/身份。入口看不见不代表入位成功，终点跟踪和车体包络用于完成判断。
- 目标为停稳后车头距终点内沿约 50 cm；采用用户已接受的 45 cm 制动距离预留。该制动距离在本次 1570 μs 配置下未实测，最终间距需现场验证，不能承诺精确 50 cm。
- 正常前进 1570 μs，不低于 1570；中位 1500，制动 1400；转向中位 1610、左右端点 1870/1350。
- 参数、观测、任务控制、执行器分离；比赛和调试共用同一控制器。没有网页心跳依赖。
- 保留真实图像/运动证据失效时的中位处置，不用无限盲走、伪造测距或假称停稳换取流程完成。

## 标定怎样接入

主摄像头用于红绿灯；第二路用于地面任务。通过既有 USB by-id 绑定，避免 `/dev/video0` 顺序变化。
两份标定都属于第二路完整 480×360 图像坐标，只允许完整画面等比例缩放，不能沿用旧包的裁剪坐标。
巡线/锥桶读取 `ground_road.json`，停车读取 `ground_parking.json`。这些标定基于既有固定姿态；相机角度、安装位置或视野改变后不能继续沿用。

导入保留原有静态/历史验证状态，没有自动宣称动态误差已验证。实测域外双条真实白线可按已知车道宽作低置信度巡线估计，日志 `lane_metric=0`；这不是新实测标定。具体来源、域限制和原件校验见 `docs/calibration.md`。
原测量车道 1.24 m、停车区 1.0 m 是标定时的场地，不被误写为当前比赛参数。

## 编译与离线观察

树莓派需已有 OpenCV 4 开发库、CMake、C++17 编译器；语音使用 `espeak-ng`。依赖安装由现场环境管理，本包不自动安装驱动、修改系统服务或抢占原控制程序。

```bash
# 在该目录内，只编译与离线测试，不发车
bash build.sh

# 只观察，默认绝不发送执行器命令
bash run_debug.sh observe --show

# 用本地录像检查停车策略，仍不控制硬件
bash run_debug.sh parking --video /path/to/secondary.avi --show
```

这里的“调试入口”是独立 C++ 命令行/观察窗口，不是旧网页。旧比赛页、调试页未修改。

## 后续现场使用

每次真实试车必须有人监管。先退出原控制程序并确认它已释放执行器，再启动本包；`--handoff-complete` 是操作人员声明，不会代替你停止旧服务。串口独占锁防止合作程序同时写入，但不是物理停稳传感器。

```bash
# 比赛：在切换区停稳，完成原遥控释放/规则要求的交接后使用
bash run_race.sh --drive --supervised --handoff-complete

# 单项停车：由现场人员摆车、监管后明确开启真实输出
bash run_debug.sh parking --drive --supervised --show
```

默认仍是只计算指令，不发送硬件。`--drive` 明确选择本车 S3 转向、S4 电调、`/dev/ttyAMA0` 1 Mbaud 驱动，不使用旧包的 Pi GPIO 12/13 直接 PWM，不自动改变云台姿态。
不要与原车服务同时运行。程序不提供5G手动驾驶模块，需与原遥控程序在切换区交接；自主开始后不依赖网页发指令。

内部执行线程独立于图像处理，350 ms 制动结束后自行回中位。若本地控制线程整整 1 秒未提供任何新输出，执行器回中位；这是处理相机/线程真实失效，并非网页心跳，也不是任务总时限。
车辆是否真正停稳来自图像地面运动证据，不把发送中位当作实测速度。无纹理、强反光或有效域不足时可能暂不能确认，这些问题必须通过现场画面检验。

## 记录和验证范围

每次运行使用独立 `runs/<编号>/`，保存 `telemetry.jsonl`、原始第二路录像，以及交通阶段主摄录像和帧时间索引。视频标称播放帧率不等于采集时间，请结合 `.frames.jsonl`；日志中的 PWM 是请求值，不是电机实际速度。
默认播报沿用现有配置“我是山东大学启航队的无人车，请为我加油！”，可在 `announcement_text` 修改；现场需检查音频设备和实际播报。
停车结束后允许按规则在 30 秒内远程手机支付 0.01 元，本包不自动付款。

`VALIDATION.json` 记录本次编译、回归和旧录像重算结果。录像重算只是对历史画面的新判断，车辆并未按新输出重新运动，不得据此认定已完赛。
历史停车片段共 109 帧，第 3 帧完成确认，此后 107 帧保持车位跟踪；识别为左侧空闲、右侧挡板。该片段没有域内实际终点观测，终点位置使用已知车位长度推断，`end_visible=0`，也没有验证停车完成。实景首三帧已作为随包回归样本，不能用“车位有效”代替“停车成功”。
本目录没有部署脚本；以后部署仍须遵循工作区的单版本核验与收尾约定。原压缩包、电脑上的历史版本和原车运行目录均未删除。
