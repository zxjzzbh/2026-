# 系统架构约定

状态：设计基线，尚未完成整车实现。以 Raspberry Pi 4B + USB 摄像头为当前开发目标，预留 STM32，默认不依赖 ROS。

## 职责

- `vision`：感知输入帧，输出道路与元素结果；不直接控制执行机构。
- `vehicle`：管理任务状态和控制权，生成高层运动指令；决定停车、等待和模式切换。
- `firmware`：执行约定的运动控制、采集编码器和底盘反馈；具体控制量待接口确认。
- `communication`：网络传输、远程客户端和链路状态；不绕过 vehicle 仲裁。
- `hardware`：真实设备与电气连接的记录，不从算法参数推断硬件。

## 数据流和时序

统一采集源向本地视觉与视频传输分发图像；实时分支使用有界队列，避免慢网络积压拖慢感知。录像逐帧评估与实时丢旧帧模式需要区分。

每条关键消息应有可追溯的序号、时间与有效性，具体字段在 interfaces 中定义。系统不得混淆“未知”“未检测到”“确认不存在”和“数据源异常”。

IMU 尚未确定型号和接法，由硬件、主控团队确定接入层并记录时间同步方式。UART 波特率、电平和协议目前均未冻结。

## 分阶段集成

1. 电脑离线运行视觉，主控用模拟感知/底盘消息。
2. 各模块通过约定接口互联，验证模式和任务切换。
3. 树莓派接摄像头实测，再与 STM32 台架联调。
4. 5G 视频与控制链路接入，测延迟、拥塞和断连行为。
5. 在允许的测试场地低速验证完整任务，保留实验记录。

该顺序是开发建议，不代表自动驾驶阶段允许人工干预。比赛行为以规则和裁判澄清为准。
