# 地面光流点对异常修复

日期：2026-10-20。基于主线 `6f38ab582a580f3c421f8f977534fbb4ea82e627`（r2），本次仅修复旧自主框架 `GroundVisualOdometry` 的投影点对不一致问题，未连接或部署小车。

## 复现与根因

原 `tools/audit_snapshot_20261008.py` 的边界样例追踪21个点，其中一个新位置移出有效地面区域。连续两次运行均在 OpenCV `estimateAffinePartial2D` 报出点数不一致断言。

旧循环先把前一帧坐标加入 `before`，再投影并加入当前帧坐标；第二次投影抛出 `ValueError` 时，旧坐标已经保留，最终形成21对20的输入。问题不是正常输入的数组类型或OpenCV版本，也不能靠裁短较长列表处理：失效点位于中间时，裁短会把后续点错配。

修复后先完成两个投影，再将整对坐标加入列表；任一投影失败则整对跳过。`GroundProjection`原有的区域、非有限值和地平线检查继续生效。原20对最少有效点门槛、运动合理性检查和位姿失效规则保持。

## 验证

新增 [test_ground_odometry.py](../../vision/tests/test_ground_odometry.py)，只替换特征检测/跟踪测量，使用真实的地面投影和OpenCV拟合：

| 检查 | 结果 |
| --- | --- |
| 旧代码运行新增14项测试 | 12失败、2通过；复现原点数不一致错误 |
| 修复后运行相同测试 | **14通过** |
| 当前帧点越界、NaN、无穷值 | 分别覆盖第一个、中间、最后一个点；整对剔除，保留其余点身份及正确速度/位姿 |
| 前一帧点无效、20对正常点 | 正确成对处理；正常测速/位姿结果保持 |
| 仅剩19对或0对 | 不调用拟合，返回`valid=false`、速度/位姿为`None` |
| 无效测量后重新取得正常点 | 可恢复速度，但不伪造丢失期间的位移，世界位姿继续无效 |
| 原审查样例，脚本保持原样 | **`raises=false, valid=true`**，不再抛异常 |
| 本地完整软件测试 | **1712通过、3个平台条件跳过** |

跳过项是Windows不支持的Unix socket/termios接口。GitHub Linux/Windows检查对应本次PR提交，结果以PR/发布页为准。

复现命令：

```sh
python -m pytest vision/tests/test_ground_odometry.py -q
python -m pytest vision/tests -q -ra
python tools/audit_snapshot_20261008.py
```

原审查样例也被纳入自动回归，异常返回会使测试失败。测试同时检查点对身份、速度与位姿语义，避免仅断言“不崩溃”而遗漏错配。这些检查用于防止此类问题再次出现，代码中未加入临时诊断日志。

## 版本与边界

最新固定版为 [source-2026-10-20-r3](../latest-code.md)，包含r2的全部功能；旧标签、源码包及历史发布清单保持固定。

PR #6停车链路使用`ConeOdometry`，其点对已采用成对保存，本次不修改该链路。摄像头标定、识别参数、PWM、租约与实测验证标志均未改变；停车路径仍有13项准备缺口，原自主框架仍有18项缺口。修复该软件异常不等于实车光流反馈或完整赛道已通过验收。
