# 视觉开发路线

当前阶段：摄像头尚未测试，先实现离线软件。以下是计划，不是已完成能力。

| 阶段 | 交付 | 验收依据 |
|---|---|---|
| 1 离线底座 | 图片/录像读取、调试叠加、结构化结果、参数配置 | 异常路径/视频结束可处理，结果可回放 |
| 2 白线循迹 | 边界、中心路径、偏差、丢线状态 | 直弯道、单边/双边丢失、阴影分别检查 |
| 3 蓝挡板 | 先确认存在，再确认移开 | 初始无挡板、蓝背景、断帧不误发车 |
| 4 斑马线 | 条纹组合和位置、多帧确认 | 虚线/阴影负样例，一次经过一次事件 |
| 5 红绿灯 | 灯具候选、亮灯状态、未知状态 | 区分灯罩颜色与实际点亮，单独设计灯具 ROI |
| 6 红/蓝锥桶 | 多目标框和底部位置 | 小目标、随机左右位置、遮挡 |
| 7 停车 | 黄白线区域、挡板与入口归属 | 两种封挡、入口未知、整车入位分开验证 |
| 8 扫码画面 | 清晰原图/裁剪输出 | 远端在规定时段取得可扫码画面 |

当前初稿是白色跑道边线、红/蓝小锥桶、蓝挡板选择空车位；不套用前辈的 A/B 标志分类流程。

第一版可优先采用 OpenCV 的颜色/亮度分割、轮廓、几何约束和跨帧确认。传统方法不足时再用独立评估数据比较小模型，不预先承诺模型或帧率。

像素位置只有经过几何标定和实车验证才能解释成距离。斑马线停车还需要相机到车头的偏移、速度和制动距离；视觉检测成功不等于停车合格。

红绿灯区域不能只看图像下半部分；锥桶很小，二维码需要足够清晰度，处理分辨率要按任务实测。固定机位是否能同时覆盖这些目标需要摄像头测试。

采集素材时保留无目标、强光、阴影和失败片段。按不同录制片段划分调参和验收集；参考室内图片不替代室外实拍。每次结果记录设备、参数、素材版本与处理耗时。

API 参考：[OpenCV HSV 分割](https://docs.opencv.org/4.x/da/d97/tutorial_threshold_inRange.html)、[相机标定](https://docs.opencv.org/4.x/dc/dbb/tutorial_py_calibration.html)。
