# 2026-11-14 比赛控制周期修复

当前主线版本为 `race-control-cadence-20261114`，同步本地已通过验证的完整源码。本次没有部署或操作车辆。

## 变更

- 比赛普通阶段的计算等待窗口由450 ms改为750 ms；后台每50 ms刷新有效指令，维持500 ms执行器租约。指令到期仍撤销前进并执行有限制动，锥桶及米制入库继续受采集证据期限约束。
- 不再把两次有效识别之间的计算间隔直接当作画面失效。帧龄、来源、帧号和时钟仍受校验；白线恢复的确认间隔与比赛计算窗口保持一致。
- 斑马线按独立地面反馈保持正式10秒停车计时；红绿灯内部恢复也可读取独立连续停稳证据。未知、过期或移动反馈不会被当成停稳。
- 退出自主驾驶与发送器关闭互斥，避免正常退出被覆盖为 `cone command sender closed`。
- 非避障阶段跳过锥桶形状、跟踪和投影处理，斑马线复用同一真实画面的识别与道路结果；日志记录完整视觉链路和分段耗时、具体恢复原因。

## 验证与边界

原始本地版本专项回归872项通过、2项跳过。公开仓库的独立回归结果记在 [verification.json](verification.json)。全部204个运行源码和网页文件均按 [SHA-256清单](source-manifest.json) 核对，Git只规范文本换行。

同一对操场现场图片在电脑上离线串行重放，斑马线整链路中位耗时由311.3 ms降至119.6 ms，新旧白线位置和斑马线识别结果一致。这是固定照片的计算耗时比较，不能当作树莓派实时性能或实车完成任务的证明。

750 ms是接受有效决策之后的计算等待窗口，与输入图像最多500 ms帧龄是不同的边界；不表示总感知到制动延迟仅750 ms。正常前进PWM仍不低于1570 μs，中位1500 μs及制动1400 μs保持原用途。

这版尚未部署到树莓派。上次确认的车端版本为 `race-control-recovery-20261114`；本次没有重新连接车辆。实际配置、近场标定、日志、录像和私人连接凭据不随此次公开发布覆盖或上传。
