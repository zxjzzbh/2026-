本版基于 11 月 20 日室外联调版，将有当前车道观测时的接近油门调到 1590 微秒，并给斑马线配置独立的反向制动脉冲。分项与全流程读取同一份 `cpp/config/race.json`。

**现场测试**　打开车端网页的“调试页”（`/debug/`），选一次项目。车辆通电、停稳后点“开始测试”。车端自动输出 3 秒中位并启动所选项目。“仅观察识别”直接打开图像。准备中或运行中均可点“结束测试”，再次点“开始测试”即可重测。浏览器记住上次选择的项目。全流程测试请在切换区交接并停稳后开始。

**如何结束一轮**　入库并确认停稳后，车辆保持中位，比赛计时冻结。调试页点“结束测试”，比赛页点“停止并释放控制”，终端按 `Ctrl+C`。录像回放在文件末尾结束。

| 项目 | 软件变化与验证 |
| --- | --- |
| 红绿灯 | 在确认同一横排三灯灯组后，比较镜片内多个分散发光点与其他灯罩的亮度差。三张标注照片分别判为红、绿、全灭。比赛控制仍要求同灯组的新鲜绿灯观测连续通过投票。 |
| 巡航油门 | 在有当前车道观测时，斑马线和红绿灯接近阶段使用 1590 微秒。短时沿用车道、绕桶及入库仍沿用原油门设置。油门是电调指令，实际车速需要实测。 |
| 斑马线 | 在双摄共同标定的 0.40–0.65 米内，将制动触发值调到 0.60 米。合成纸条回放在约 0.65 米时继续接近，在约 0.58 米时请求 1300 微秒反向脉冲，目标持续 0.12 秒，由输出线程在到时后的首个写入周期回到 1500 微秒中位。若回中位后连续多帧确认仍向前滑行，最多补一次。确认停稳后开始累计 10 秒。 |
| 巡线 | 低亮度处补找比邻近路面更亮的狭窄白线，继续检查形状和车道宽度。对四张历史车载图统一降至原像素值的 48%，每张重复 6 帧。旧版在压暗的 24 帧中有效 0 帧，新版有效 24 帧。这是人工压暗的静态回放。 |
| 锥桶 | 继续使用 11 月 15 日原比赛算法。网页分别显示主摄和地面相机在当前帧确认的桶数。连续输入三组历史双摄图，稳定帧两路分别报告 1/1、2/2、0/0 个。撤桶后仍出现的普通蓝色区域不计作桶。该序列因车道证据不足而保持中位，实际绕行间距和连续双桶通过仍需上车验证。 |

1300 微秒取自前进／制动／倒车档的架空校准记录。此次选用的 0.12 秒是短脉冲初值。请在封闭场地实测从 1590 微秒接近时的停车落点，并观察停稳后有无倒滑。红灯和入库仍用原有的 1400 微秒制动。

### 锥桶版本

比赛全程和调试页的锥桶单项共用同一套双摄识别、选边、绕行和回中逻辑。原版的比赛入口是 `race_flow.py`，版本为 [race-flow-repair-20261115](https://github.com/zxjzzbh/2026-/tree/7db04fb03c79dee57718d6de666259a9e246019a)。

锥桶配置从该提交的 `cone-trial.json` 和两路相机的历史地面参考加载。本车使用 1.17 米赛道宽度和 1570 微秒前进设置。绕桶采用原版 1.5 转向增益。缺少有效指令时保持中位等待，保留本轮任务。配置目录中原有的 10 月标定文件用于复现 C++ 巡线地面映射。

## 构建与回放

在源码根目录运行。车端需要 C++17 编译器、CMake 3.20 或以上、OpenCV 4 开发库，以及同一个 Python 3.10 或以上环境的开发库、NumPy 和 OpenCV。Windows 构建的检查结果记录在下节。树莓派需要在本机编译。

```bash
bash cpp/build.sh
bash cpp/run_race.sh --video /path/to/H65.avi --traffic-video /path/to/USB2.avi
```

这条命令只读录像。第一路参数是看地面的 H65，第二路是 USB2.0 主摄。请使用起点同步、保留完整 4:3 视野的素材。只有 H65 录像时可省略 `--traffic-video`，程序用单路证据回放。单项可运行 `bash cpp/run_debug.sh obstacle --video /path/to/H65.avi`，将 `obstacle` 换成 `zebra`、`traffic` 或 `parking` 即可检查相应任务。

| 路径 | 用途 |
| --- | --- |
| `cpp/config/race.json` | 两路相机、标定入口、油门、转向和队名。 |
| `cpp/src/main.cpp`、`cpp/src/controller.cpp` | 比赛入口、状态切换、制动和停车交接。 |
| `cpp/algorithms/hybrid.py`、`cpp/algorithms/legacy/` | 旧模块的比赛适配、图像算法和绕桶策略。 |
| `vision/src/carvision/`、`vision/web/` | 新版 5G 网页、远程控制与接管。 |
| `cpp/runs/<编号>/telemetry.jsonl` | 默认脚本生成的逐帧日志。可查看任务阶段、斑马线距离状态、红绿灯投票、可见桶数、通过桶数和控制指令。 |

需要重打整包时，在源码根目录运行 `python3 cpp/tools/pack_release.py ../smartcar_oneclick_zebra_reverse1590_20261120.zip`。压缩包内的 `MANIFEST.json` 记录每个源码文件的 SHA-256 校验值。

## 行驶中遇到丢帧

- 主摄和地面相机各自重新打开原设备。地面画面持续中断时，车辆收油、保留当前任务并继续尝试读帧。画面恢复后重新判断道路。
- 绕桶画面短时重复时，执行器保留上一条仍有效的控制，不刷新其有效期。持续缺少边界或没有可通行空间时保持中位。重新确认车道后继续本轮，已经通过的桶数保留。
- 双桶完成并回中后，当帧就使用停车接近策略。有可行车道时连续驶向车位。
- 串口写入失败会报告执行器故障。此时软件无法确认车辆已收到指令。

- 双摄组合回放使用实拍挡板和斑马线帧、合成横排灯和合成锥桶场景。实际比赛入口从等挡板运行到双锥桶阶段，验证了斑马线制动、停稳计时、红灯停车、绿灯放行。单独回放还验证了另一台相机独自变绿不会解除已确认的红灯停车。
- 两个不同目标的接近、退出和回中用合成观测序列检查。控制器测试单独验证了绕桶完成后切入停车，拿到有效车位与停稳证据后结束。反光锥桶样图中，能识别蓝桶，但道路双边界证据不足时会等待。
- 本次没有连续实车双桶绕行到入库的录像，也未进行车端实时性、实际绕桶间距和制动落点测试。11 月 19 日版的斑马线制动触发值为 0.40 米。

## 11 月 20 日停车进场复核

旧版在进场远景把浅黄胶带分割成了几段，入口线与车位侧线接不上。反光段的暖色亮斑与胶带连在一起，原来的直线组合也无法稳定确认车位。停车检测器现在用胶带相对邻近地面的亮度差提取入口，再用相连的两条侧边、可见地面和相邻蓝挡板核对空闲方向。在地面反光与胶带颜色接近时，用入口线中段复核朝向。只有标定区域内的观测参与测距。
