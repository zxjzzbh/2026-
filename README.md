# 当前 C++ 与 5G 全套源码：感知与流程修复

版本：`car-cpp-perception-20261119`。
在 `car-cpp-board-start-20261119` 上继续修改。本包包含源码与离线回归，实际安装结果以本次部署回执为准；没有实车发车验收。

## 本次修改

- 保留现有 C++ 主流程、5G 控制与交接、比赛页和调试页；未搬回旧 Python 自主控制器。
- 斑马线先找成排白纸，再单独测距。低彩度与周围亮度差共同排除浅红跑道；同排结构排除孤立亮块；遮挡后的纸片边缘不冒充真实近沿。
- 根据用户指定接入 2026-10-24 实测表 `cpp/config/calibration/crosswalk-distance-20261024.json`。H65 第二路的 40/50/65 cm 对应近沿 y=342/316/289，480×360 全幅。表中距离从车头计算，控制器的后轴坐标只转换一次。表范围外不外推，也不退回 10/07 road 映射。
- 斑马线远于 65 cm 时仍可识别并继续接近；进入有效区后按默认 45 cm 制动距离加 15 cm 目标余距触发。确认白纸但边缘被裁切/遮挡时输出一次制动并说明距离未确认，不把该位置报告成实测停距。停留仍为确认静止 10 秒。
- 有界地面模型的白线与锥桶现在可以共同进入避障。必须保持当前成对边界、赛道宽度一致与误差余量；纯图像比例仍不是 20/50 cm 的实测依据。模型只允许有限横向延伸，近远有效深度和原实测区域没有被扩大。
- 红绿灯没有证据时不再以 25 秒到期跳过任务；旧绿灯状态不再持续授权放行，须有当前对应灯壳的绿灯。
- 实车制动阶段等待本次执行器完成回执；离线回放仍用明确的计时模拟。回执只证明脉冲执行，不等同于物理停稳。
- 停车完成必须当前终点可见；补进需要新的制动事件，并按同样的制动距离提前刹车，不等到目标点才刹。已停在 60–95 cm 时，现有 45 cm 制动模型不足以可靠完成短补进，因此明确等待，不假报完成。
- 运行记录增加斑马线候选/测距状态、模型来源、锥桶未映射数量、制动事件与实际输入路径，便于区分识别、换算和运动故障。

## 摄像头与标定用途

- 第二路 H65：路面、斑马线、锥桶、停车。
- 主摄像头 USB2.0 / YT-FAY：红绿灯。
- `crosswalk-distance-20261024.json` 只用于斑马线近沿纵向距离，不是完整地面映射；不能替代避障横向距离或停车映射。
- `ground_road.json` 和 `ground_parking.json` 保留原文件，本次没有把历史验证标志改成“当前已验证”。24 号原始表也按原字节保留，其 `runtime_detector_verified`、`physical_stop_verified` 仍为 false。
- 原地面、停车映射中已有二维及横向测量点，它们全部保留；这不等于画面任意位置都在对应标定有效区域内。
- 现有室外录像中的白线多数只能提供图像引导，部分锥桶仍在地面映射有效深度之外。接口修复不代表这份录像已能完成实车避障；不能凭离线测试宣布比赛通过。

## 验证与入口

使用 `cmake -S cpp -B build`、`cmake --build build`、`ctest --test-dir build --output-on-failure`。
本地九组 CTest 通过，包含 28 项 5G 检查、真实画面识别到控制器回归及 JPEG/MJPG 重编码误报检查。41 张保存画面的重复静态回放中，4 张斑马线画面确认，其余 37 张没有确认斑马线。这不代表完整动态录像/停车距离/帧率实车验收。
所有测试为离线图像、模拟观察或假执行器，不发车。车端测试结果记录在部署回执。

部署后入口仍是 `/competition/` 和 `/debug/`，服务启动只预览，不自动准备或发车。
后续部署必须按工作区 `AGENTS.md`，保留车端实测配置、录像和日志，完整校验并完成单版本清理。
旧 `cpp/docs/` 的 R2 审查/操作报告是历史记录；若描述与本文件冲突，以本版源码及本文件为准。
